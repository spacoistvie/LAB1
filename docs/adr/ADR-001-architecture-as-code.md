# ADR-001: Архитектурные решения ведём в Architecture-as-Code формате (MADR + Git)

* **ID:** ADR-001
* **Статус:** принято (Accepted)
* **Дата:** 2026-09-21
* **Авторы:** Булатова Элина Эльмаровна, группа ДИФ11
* **Реестр ADR:** [docs/adr/README.md](./README.md)

## Контекст и проблема

Архитектурные решения принимаются постоянно, но «теряются» в переписке и
презентациях. Нужен машиночитаемый, версионируемый способ фиксации решений,
диаграмм и их прослеживаемости к требованиям (ASR).

## Решение

1. Все диаграммы — исходный код: PlantUML (`docs/architecture/*.puml`),
   Context Mapper DSL (`docs/architecture/*.cml`). Рендеры — только доказательства
   (`evidence/*.png`).
2. Решения фиксируются по шаблону **MADR** (Markdown Any Decision Record) в
   `docs/adr/ADR-NNN-*.md`; реестр — `docs/adr/README.md`.
3. Сборка — одной командой `make build-docs` (Makefile), проверка — `lint.sh`.

## Последствия

- **+** любое решение прослеживается к варианту-альтернативе и к ASR;
- **+** ревью архитектуры через pull-request, история изменений через git log;
- **−** требуется дисциплина: несинхронизированная диаграмма делает документацию
  ложной; риск снижается скриптом `lint.sh` и автосборкой в CI.
